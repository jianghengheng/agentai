# User CRUD implementation

Implement the user's requested CRUD operations over the existing Prisma 8 User contract.

- Keep the existing `/user` route and use POST, GET, PATCH and DELETE for resource operations.
- Allow email and optional name; reject unknown fields and invalid email/name values. Allow name=null to clear it. Reject email=null and empty updates.
- Support GET /user with limit (default 20, max 100) and offset (default 0), and GET /user/:id. IDs are UUIDv4 as generated by the current contract.
- Return 201 for create, 200 for reads/updates and 204 for delete. Map missing users to 404 and PostgreSQL email uniqueness violations to 409.
- Wire UserModule into AppModule and retain one root ObserveModule registration.
- Add unit coverage for database error handling and HTTP coverage for routes and validation before implementation. Then build, lint, run tests and exercise the compiled app against the supplied Docker PostgreSQL with temporary users cleaned up afterwards.

No database schema change is required. Execute in place because this workspace is not a Git repository.

## Completed verification

- Unit tests: 9 passed. A concurrent rerun timed out in the original AppController setup; a sequential rerun passed in 1.50 seconds.
